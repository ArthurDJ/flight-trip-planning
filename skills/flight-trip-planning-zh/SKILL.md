# 机票决策 skill（中文版）

## 这个 skill 解决什么

搜索引擎回答"哪班最便宜"。这个 skill 回答 **"我们到底该订哪一班"**，简单行程也适用（快速模式），而答案取决于搜索引擎不管的那些事时尤其需要：

- **计划可能变**：签证或移民审批未定、工作学业日期未定、家庭安排。灵活性是有价格的，这个 skill 把它算成钱。
- **退款必须退现金**，不能是航司 credit（例如旅客要搬到别的国家，或很少再坐这家航司）。
- **跨境行程**：入境证件、在哪里过海关、转机时要不要重新托运行李。
- **替别人订票**（伴侣、父母、同事）：旅客需要一眼能看懂的结论，订票人需要能核对的依据。

它把这些变成硬性筛选条件和"多花多少钱换什么"的取舍，在航司官网核实候选，然后交付决策。**订票和付款由本人完成，agent 从不代劳。**

## 范围

**这里处理**，细节见 `references/scenarios.md`：单程 vs 往返、开口程和多城市、带行李的家庭、临时出行、同一订单多名旅客、审核其他 agent 的结果。

**这里不处理。** 用一句话说明，并指向合适的工具：

| 需求 | 用什么 |
|---|---|
| 实时搜索、最便宜日期、价格追踪、该买还是该等的预测 | Google Flights、Kayak、Skyscanner、Hopper（预测不保证准确） |
| 里程和积分最优化 | 航司官网和兑换工具；用户已有的里程方案仍可参与比较（`references/scenarios.md` → 里程和积分方案） |
| 隐藏城市票、"Hacker Fares"、自助中转技巧 | 默认排除 |
| 酒店、整体行程 | 不在范围内 |
| **订票之后**或航司取消之后的退款、credit、赔偿申请 | 订后退款决策类 skill；如适用，提一句航司取消时的退款权利（`references/regions.md` → 带日期的事实） |

搜索工具的结果只用来**发现航班**，不作为最终价格。

## 模式

选最轻的一档，出现触发条件再升级。

| 模式 | 适用 | 提问数 | 输出 |
|---|---|---|---|
| **快速**（简单行程默认） | 境内、日期固定、无特殊约束 | 0–2：只问消息里没说的 | 精简卡（前 3 名）+ 推荐 |
| **标准** | 任一：计划不确定、跨境、替别人订、超过 2 位旅客 | 6–10 | 对比表、取舍说明、旅客精简版 |
| **详细** | 影响大、日期 × 机场组合多、或有第二个 agent 审核 | 完整问询 | 带版本号的需求文档、完整结果文件、审核、出票记录 |

升级触发：旅客可能取消；行程跨境；转机依赖每天只有一班的航班；签证或移民身份待定；用户要求审核另一个 agent 的结果。

## 各模式的流程

| 步骤 | 快速 | 标准 | 详细 |
|---|---|---|---|
| 1. 问询（`references/templates.md` → 问询） | 从消息推断；只问缺少且会改变决策的；说明默认值 | 标准问题 | 完整问询 + 需求文档 |
| 2. 档位（`references/decision-framework.md` → 偏好档位） | 默认均衡，除非用户另说 | 与用户一起选 | 选定并写下兑换率 |
| 3. 硬性筛选 | 日期、时段、行李 | + 退改类别、证件、同一张票 | + 各日期时段限制、最长时长和转机次数 |
| 4. 发现候选 | 按给定日期搜一轮 | 每一天、每个时段；倒推法（`references/verification.md` → 倒推法） | + 所有可接受机场；价格矩阵 |
| 5. 官网核实（`references/verification.md` → 官网核实） | 推荐方案和第二名 | 每个候选 | 每个候选 + 查询记录 |
| 6. 真实总价和灵活性（`references/decision-framework.md`） | 票价 + 行李；计划可能变时才算盈亏平衡 | 完整真实总价；盈亏平衡判断 | 同左，写出输入 |
| 7. 可行性（`references/verification.md` → 转机评估、`references/regions.md`） | 有转机时才拆转机步骤 | + 跨境规则、证件、时差 | 同左，去回程分别权衡 |
| 8. 决策并解释 | 前 3 名，用金额写取舍 | 同左 + 更便宜或更近的选项为什么落选 | 同左 |
| 9. 交接（`references/templates.md`） | 精简卡 | + 旅客精简版、出票清单 | + 完整结果文件、审核、出票后核对 |

快速模式要保持简短。篇幅预算：总共大约 250 个英文单词的篇幅（中文按同等信息量），由精简卡、一句话推荐、最多 2 个问题（只问答案会改变选择的）和最多 2 条简短提示组成。不写需求文档，除非某条规则适用否则不套地区模块，也不附出票清单：用一句话提出可以提供。

## 缺少工具时

- **没有搜票工具**：请用户贴搜索结果、链接或截图，基于这些工作。
- **没有浏览器**：无法在航司官网核实价格。每个价格都标"由你提供，未在航司官网核实"，说明可能变化的地方（票种、行李、税费），并给出出票清单（`references/templates.md` → 出票清单），让用户付款前自己核对。
- **没有网页搜索**：使用 `references/regions.md` 里的规则并注明"核实日期"，说明需要重新核实。
- 任何情况下都不凭记忆补空：不编造航班号、时刻、价格或费用。典型时刻表只能写成"通常如此，未核实"。

## 核心规则

1. **先结论**：每份交付物开头先给推荐。
2. **绝不订票、付款、占座、登录或输入账号密码**；遇到登录或验证页面就跳过，留给本人处理。
3. **绝不占用用户正在用的浏览器标签页**；新开标签页，用完关掉。
4. **第三方结果只是线索**；最终价格、票种、退改条款以航司官网同一行程为准。
5. **口径不同不比较**：单程与往返、可退与不可退、含与不含行李的价格，不加"口径"列就不放在同一列。
6. **每个推断标置信度**（高 / 中 / 低）和依据；查不到写"未核实"，不推测。
7. **不悄悄放宽硬性条件**：无解就报告无解和原因，由用户决定。
8. **规则会变**：行李费、退改政策、入境规则、时区在执行时核实，并记录查询时间。
9. **始终标两地时间**：跨时区的起降写成"当地时间（另一地时间）"。

## 输出

- **精简卡**（快速模式）：前 3 名、真实总价、退改类别、时刻、转机、每条一句取舍。
- **对比卡**（标准及以上）：增加两地时间、转机风险和每个价格的口径。
- **旅客精简版**（标准及以上）：大白话，只放前 3 名，3–5 条注意事项（怎么取消、行李、证件）。
- **交接消息**（涉及其他 agent 时）：内容自包含，不引用对方打不开的文件。
- **完整结果文件和审核**（详细模式）。
- **出票记录**：出票后核对完成后写入。

模板见 `references/templates.md`。
